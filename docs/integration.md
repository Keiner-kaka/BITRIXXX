# Подключение пилота к коробочному Bitrix24

Приложение использует ту же схему взаимодействия, что исходная статичная версия: официальный BX24 SDK и REST в авторизации установленного приложения. Здесь описана настройка; реальные вызовы на вашем портале при сборке не проверялись. Начинайте с тестовой сделки и отдельной папки Диска.

## Предварительные условия

- Администратор Bitrix24 может создавать локальные приложения и регистрировать встраивания.
- На портале доступны необходимые REST-методы CRM, каталога, Диска и встраивания; набор методов зависит от версии коробки и установленных модулей.
- Статичные файлы приложения доступны по HTTPS из браузера менеджеров и разрешены политиками встраивания портала.
- Приложению предоставлены права `crm`, `catalog`, `disk`, `placement`; у менеджера есть права на нужные товары, сделку, файлы и папку истории.

Входящий вебхук не создаёт вкладку и не заменяет контекст установленного приложения. Секреты в код и JSON не добавляйте. Доступ `BX24.init()` за пределами портала не означает успешную авторизацию: локальная демонстрация работает отдельно.

## Размещение и установка

1. Разместите `index.html`, `index.php`, `install.html`, `install.php`, `styles.css`, `src/` и `data/` с сохранением относительных путей. Сборка не нужна. Для коробки используйте отдельный HTTPS-каталог на собственном PHP-сервере.
2. Если ваша версия Bitrix24 поддерживает загрузку ZIP статичного локального приложения, используйте архив с `index.html` в корне. При отсутствии такого режима укажите HTTPS-адрес обработчика размещённого приложения.
3. Укажите обработчик приложения `https://your-host.example/kp/index.php`: он принимает POST Bitrix24 и передаёт в браузер только ID сделки. Статичный `index.html` используйте, если хостинг вашего портала поддерживает POST для этого адреса. URL должен открываться в браузере и допускать показ во фрейме вашего портала; заголовки `X-Frame-Options` и CSP `frame-ancestors` не должны запрещать это.
4. Укажите обработчик установки `https://your-host.example/kp/install.php`, откройте его через установку приложения и нажмите «Завершить установку». Он вызывает `BX24.installFinish()` только по кнопке после готовности SDK. Для статичного хостинга предусмотрен `install.html`.
5. Откройте установленное приложение и его настройки. Регистрация вкладки выполняется отдельным действием «Зарегистрировать вкладку сделки»; она не запускается при каждом расчёте.

Концептуально регистрация выглядит так; `HANDLER` заменяется адресом приложения в вашем размещении:

```javascript
BX24.callMethod('placement.bind', {
  PLACEMENT: 'CRM_DEAL_DETAIL_TAB',
  HANDLER: 'https://your-host.example/kp/index.php',
  TITLE: 'Конструктор КП'
}, result => {
  if (result.error()) {
    // Показать безопасное сообщение без URL с токенами.
    return;
  }
  // Вкладка зарегистрирована для приложения.
});
```

После регистрации откройте заново карточку тестовой сделки. Вкладка получает ID сделки из параметров placement. При запуске приложения вне карточки можно явно указать ID сделки в настройках и подключить её.

Официальные описания: [вкладка CRM](https://github.com/bitrix-tools/b24-rest-docs/blob/main/api-reference/widgets/crm/detail-tab.md), [placement.bind](https://github.com/bitrix-tools/b24-rest-docs/blob/main/api-reference/widgets/placement-bind.md), [SDK Bitrix24](https://api.bitrix24.tech/api/v1/).

## Справочники на Диске

1. Возьмите [relations.example.json](../data/relations.example.json) и [coatings.example.json](../data/coatings.example.json). Для первого испытания допустимы демонстрационные связи; для реальных товаров замените все ID.
2. Загрузите оба файла на Диск. В настройках приложения заполните `relationsFileId` и `pricesFileId` — ID файла связей и файла покрытий.
3. Для общей истории создайте отдельную папку и заполните `historyFolderId`. Без этого сохранение остаётся локальным в браузере.
4. Нажмите загрузку справочников. Приложение проверяет структуру JSON перед использованием. Сначала проверьте связи и коэффициенты, затем выбирайте товар в тестовой сделке.

Загрузка файла выполняется через `disk.file.get` и полученный адрес скачивания. Доступ к файлу по REST и возможность скачать его из браузера — отдельные условия. Если скачивание блокируется CORS, сначала настройте разрешённый origin на вашем сервере/Диске. Для пилота можно скачать файл обычными средствами портала и выбрать его в настройках приложения как локальный JSON. Это загружает справочник в приложение, но не создаёт синхронизацию с Диском.

Не отключайте TLS-проверку и не размещайте токен в URL вручную. Перед передачей диагностических сообщений удаляйте ссылки скачивания и параметры авторизации.

## Каталог и запись в сделку

Приложение читает торговое наименование и базовую цену каталога. Производственное название и вес не являются условиями выбора товара. Цена должна быть доступна и подтверждена: отсутствие цены не подменяется нулём. Валюта товара должна совпадать с валютой расчёта. Если версия коробки или тип SKU не поддерживает чтение нужных данных, требуется диагностика и настройка, а не запись случайной позиции.

Сохранение версии КП и применение её к сделке — разные действия. Кнопка применения **заменяет весь текущий набор товарных строк сделки** выбранным предложением. До записи приложение показывает подтверждение, повторно читает товары и сравнивает их с ранее показанным состоянием; после записи читает результат для проверки. Повторное применение не должно добавлять дубликаты.

Если другой менеджер изменил товары между чтением и подтверждением, обновите данные и повторно проверьте состав. REST не предоставляет здесь общей транзакции для строк и суммы сделки; проверка до/после уменьшает риск, но не блокирует изменения другого пользователя в момент записи. Не используйте прототип как единственный механизм согласования в рабочем портале.

Уже существующие строки сделки могут содержать договорные цены. Их чтение не означает, что эти цены равны актуальным базовым ценам каталога. Перед применением проверьте сумму, скидки, налоги и возможные автоматизации вашей сделки: прототип рассчитывает предложение по своим правилам, а портал может применять дополнительные настройки.

## Общая история и права

При настроенной папке приложение читает JSON-снимки этой сделки и сохраняет новые отдельными файлами. Наличие ID папки само по себе не гарантирует общую историю: загрузка и скачивание должны фактически работать с правами пользователя. Сообщение об ошибке сохранения на Диск не является подтверждением общей записи; локальную копию можно выгрузить отдельно.

Приложение не перезаписывает старые версии, но пользователи с соответствующими правами могут менять файлы на Диске. В промышленном модуле нужны серверное хранение, контроль изменений и единые правила конкурентного редактирования. Перед пилотом проверьте, что второй менеджер видит сохранённую версию, а пользователь без прав не получает данные через приложение.

## Приёмка на тестовом портале

1. Вкладка открывается из сделки, её ID и клиент отображаются правильно.
2. Выбирается реальный торговый товар; базовая цена и валюта совпадают с каталогом.
3. Справочники загружаются с Диска; у товара с несколькими чертежами требуется выбор; документы открываются с проверкой прав.
4. Сохраняются два варианта и несколько версий; изменение текущего расчёта не изменяет предыдущие снимки.
5. При общей истории второй менеджер видит сохранённые версии после загрузки.
6. Применение согласованной версии заменяет строки тестовой сделки; повторное применение не создаёт дубликаты; фактические строки и сумма проверены после записи.
7. Изменение сделки другим менеджером до применения обнаруживается; отсутствие цены, доступа к файлу или прав приводит к понятной ошибке.

Формирование промышленного DOCX/PDF, бизнес-согласование, автодобавление комплектующих и серверная защита расчёта потребуют отдельного этапа.

При одновременном сохранении двумя менеджерами номера версий могут совпадать; уникальные идентификаторы снимков предотвращают перезапись файлов. Прототип не выделяет НДС в печатном КП; налоговые правила нужно проверить на тестовом портале.
