# Форматы данных

Справочники — JSON в UTF-8. Для загрузки с Диска Bitrix24 указывается ID **файла**, а для общей истории — ID **папки**. Цены металла и наименования покрытий загружаются отдельно. Прямое чтение XLSX не реализовано: данные таблицы нужно преобразовать в JSON.

## Наименования покрытий и настройки расчёта

[Пример](../data/coatings.example.json):

```json
{
  "version": "coatings-2",
  "currency": "RUB",
  "formulaMode": "catalog",
  "rounding": "line",
  "coatings": [
    {"code": "none", "name": "Без покрытия"},
    {"code": "zinc", "name": "Горячее цинкование"},
    {"code": "paint", "name": "Окраска", "supportsRal": true},
    {"code": "zinc_paint", "name": "Горячее цинкование + окрашивание RAL", "supportsRal": true}
  ]
}
```

`code` должен быть уникальным, `name` используется в КП. Старое поле `coefficient` допускается при загрузке, но игнорируется: К3 задаётся в товарной строке. Поле `prices_per_kg` из старого объединённого файла не загружает цены при импорте покрытий; этот файл можно отдельно выбрать в импорте цен металла.

`version` — метка версии справочника. Она не определяет формулу. После проверки настройки получают `calculationVersion: 2`. `formulaMode` принимает `catalog` или `excel`, `rounding` — `line` или `unit`. По умолчанию валюта `RUB`; цена и валюта расчёта должны совпадать. Автоматической конвертации нет.

## Цены металла

[Пример](../data/metal-prices.example.json):

```json
{
  "version": "metal-1",
  "currency": "RUB",
  "prices_per_kg": {
    "16": 120,
    "17": 135.5
  }
}
```

Ключи `prices_per_kg` — положительные целые ID товаров Bitrix24. Цена за килограмм должна быть конечным неотрицательным числом; десятичная запятая допустима в строковом значении. Если `currency` не указана, используется `RUB`. Пустой справочник и некорректные значения отклоняются до применения.

В настройках приложения указывается отдельный ID файла цен металла. Загрузка с Диска и выбор локального JSON используют один формат. При отсутствии цены товара Excel-расчёт не готов к сохранению и генерации; ноль автоматически не подставляется. Изменение справочника влияет на новые расчёты, а не на архивные снимки.

## Товарная строка и формулы

Общие поля строки: `productId`, `productName`, `currency`, `quantity`, `coatingCode`, `ralColor`, `k1`, `k2`, `k3`, `executionTerm`. Для каталога нужна `basePrice`; для Excel — `pricePerKg`, `weight` и `fasteners`.

| Режим | Цена единицы |
| --- | --- |
| `catalog` | `basePrice × k1 × k2 × k3` |
| `excel` | `pricePerKg × weight × k1 × k2 × k3 + fasteners` |

Сумма строки равна цене единицы, умноженной на `quantity`. `weight` — вес одной единицы в кг, `fasteners` — цена метизов на одну единицу. К3 — ручной коэффициент покраски и покрытия. Наименование покрытия не участвует в расчёте. Старые `extraCoating` и `delivery` больше не добавляются к цене.

`executionTerm` — свободный текст срока исполнения конкретной строки, например `20 рабочих дней`. Он сохраняется в снимке и передаётся в строку документа. Это не общий срок отгрузки и не обязательная календарная дата.

К1, К2 и К3 допускают ноль и отрицательные значения. Пустые и нечисловые значения, бесконечность, неположительное количество и вес, отрицательные цены ошибочны. Для каталога вес не требуется. Невалидная строка блокирует готовность всего предложения; частичный итог не используется как готовое КП.

При `line` округляется `rawUnit × quantity`, а отображаемая цена единицы округляется отдельно. При `unit` сначала округляется цена единицы, затем её произведение на количество. Итог — сумма округлённых строк. Округление до двух десятичных знаков; в режиме `line` произведение отображаемой цены на количество иногда отличается от суммы строки на несколько копеек.

## Шаблон документа

Исходный пользовательский [DOCX](../data/templates/kp-yuzm-bitrix24.docx) хранится без изменения. После регистрации его ID задаётся администратором в общих настройках приложения Bitrix24, ключ `yuzmQuoteTemplateId` (`app.option.get` / `app.option.set`). Черновики не переопределяют этот выбор. Старое поле черновика `documentTemplateId` и браузерный `defaultDocumentTemplateId` удаляются при загрузке; исторические снимки остаются неизменными.

| Метка DOCX | Значение |
| --- | --- |
| `{ProductsIndex}` | Номер строки |
| `{ProductsProductName}` | Наименование товара |
| `{YuzmCoating}` | Наименование покрытия с `RAL <ralColor>` для окраски |
| `{ProductsProductQuantity}` | Количество |
| `{ProductsProductPriceBrutto}` | Расчётная цена единицы |
| `{ProductsProductPriceBruttoSum}` | Сумма строки |
| `{YuzmDeliveryPeriod}` | `executionTerm` строки |
| `{TotalSum}` | Итог сохранённого КП |
| `{RequisiteRqCompanyName}` | Клиент сохранённого КП |

Товарная таблица передаётся через `KpItems` с `ArrayDataProvider` и переопределением меток таблицы: содержимое не берётся из текущих товаров сделки. `{DocumentNumber}` и `{DocumentCreateTime}` заполняет генератор Bitrix24.

Поля `draft.documentFields` принадлежат конкретному варианту и копируются в `snapshot.documentFields`. Они соответствуют меткам условий и менеджера в файле: `YuzmPaymentTerms`, `YuzmFastenerTerms`, `YuzmDocumentsTerms`, `YuzmDeliveryTerms`, `YuzmValidityTerms`, `YuzmManagerPosition`, `YuzmManagerName`, `YuzmManagerPhone`. Это редактируемый текст для документа; связи с техническими файлами не создаются. Дублирование варианта копирует условия, после чего варианты редактируются независимо. Восстановление после перезагрузки сохраняет условия каждого варианта.

Поле строки `ralColor` — необязательный текст до 100 символов. Оно используется для окраски и комбинации цинкования с окрашиванием; для других покрытий игнорируется. В справочнике можно указать `supportsRal:true` для другого окрашиваемого покрытия. Старые справочники автоматически получают вариант `zinc_paint` в редакторе, если комбинация ещё не представлена. При смене покрытия номер остаётся в строке и возвращается при выборе окраски. Сам номер и покрытие не влияют на цену.

Для `YuzmFastenerTerms` доступны предустановки «В стоимость включен крепеж на базе болтов (гальваническое покрытие).», «Крепеж в комплект не входит.» и «В стоимость включен крепеж на базе шпилек (гальваническое покрытие).». Выбранный текст можно редактировать; он сохраняется в версии.

Варианты оплаты 40/60, 50/50 и 100% предоплаты подставляют текст в поле `YuzmPaymentTerms`; менеджер может изменить его вручную. Начальные значения из предоставленного образца:

| Поле | Начальный текст |
| --- | --- |
| `YuzmPaymentTerms` | 50% предоплата + 50% по факту готовности к отгрузке. |
| `YuzmFastenerTerms` | В стоимость включен крепеж на базе болтов (гальваническое покрытие). |
| `YuzmDocumentsTerms` | На продукцию выдается паспорт, сертификат соответствия. |
| `YuzmDeliveryTerms` | Доставка в г. Краснодар, Ставропольская, 19 производится силами поставщика. |
| `YuzmValidityTerms` | КП действительно в течение трех рабочих дней. |

Поля должности, имени и телефона менеджера автоматически заполняются из профиля текущего ответственного при открытии сделки, если выдано `user_basic`. Телефон — только `WORK_PHONE`; если он пуст, значение вводится вручную. В демо подпись изначально пуста. Все три поля редактируются в варианте; `draft.managerOverrides` сохраняет ручную правку отдельно для каждого поля. Адрес доставки в образце не считается адресом каждой сделки; его нужно проверить и заменить для конкретного КП.

## Варианты, снимки и совместимость

Редактируется черновик выбранного варианта. Сохранение создаёт снимок с собственным ID и номером версии. Новые снимки имеют `schemaVersion: 2`, содержат исходные строки с К3 и сроками, рассчитанные цены, клиента, шаблон, условия и поля менеджера, использованные настройки. Правки черновика и справочников не пересчитывают сохранённую историю. Документы и их ссылки учитываются отдельно от снимков в данных варианта этого браузера.

Снимки `schemaVersion: 1` открываются с исходными сохранёнными значениями и суммами. При восстановлении старого **черновика** каталога прежний множитель покрытия переносится в К3, чтобы сохранить расчёт. Старый черновик Excel требует заполнения цены за кг и веса: новая формула не трактует прежнюю базовую цену как стоимость металла.

При общей истории создаются отдельные файлы:

```text
yuzm-kp-deal-{dealId}-{variantId}-v{version}-{snapshotId}.json
```

Демонстрационные товары `16`–`19` не являются данными вашего портала. [prices.original.example.json](../data/prices.original.example.json) сохранён как исходный пользовательский пример; наличие старых коэффициентов в нём не делает их действующими множителями.

Настройте права папки на Диске. Не записывайте токены, пароли и ссылки с авторизацией в справочники или снимки. Уникальные имена предотвращают перезапись приложением, но не заменяют централизованное назначение версий при работе нескольких менеджеров.

С версии 2.1.0 создание документа обязательно переносит товары снимка в сделку и проверяет запись. Предпросмотр и сохранение версии не меняют товары. Удалённые дата отгрузки и флаг «Нестандарт» могут присутствовать только в старых неизменяемых снимках.

С версии 2.2.0 подпись автоматически берётся у текущего ответственного за сделку. В снимках остаются три обычные текстовые метки `YuzmManagerPosition`, `YuzmManagerName`, `YuzmManagerPhone`; изменение профиля не меняет архивы. При передаче в соседние метки DOCX добавляется разделяющий пробел после должности, если оба поля заполнены. Исходный текст снимка и файл DOCX не меняются.

С версии 2.3.0 новый документ из любой сохранённой версии создаётся по текущему общему шаблону, повторно прочитанному с портала перед генерацией. Поле `documentTemplateId` в снимке остаётся сведением о выборе на момент сохранения и не управляет генерацией. Товары, цены, сроки, условия и подпись берутся из снимка. Уже созданные документы сохраняются со своими ID и шаблонами; после смены общего шаблона можно создать новый документ из той же версии.

## Вариации товаров

С версии 2.4.0 `productId` строки может быть ID вариации (торгового предложения) Bitrix24. `productName`, `basePrice`, `currency` относятся к этой конкретной вариации. Дополнительные поля `isVariation:true`, `parentProductId`, `parentProductName` сохраняют связь с основным товаром для интерфейса и не изменяют формулу. В `prices_per_kg` ключом служит `productId` самой вариации. Значение для основного товара не используется как запасное. Номер схемы остаётся 2: дополнительные поля необязательны, старые снимки не меняются.
