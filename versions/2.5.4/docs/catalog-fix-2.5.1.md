# ЮЗМ · Конструктор КП 2.5.1

Исправления поиска каталога и обработки цен относительно приложенной версии 2.5.0.

## Что изменено

- Загружаются все страницы доступных каталогов. Ограничение поиска в 500 результатов снято.
- В поиске доступны обычные товары, услуги, основные товары SKU и их вариации. Неактивные позиции также показываются с отметкой «неактивен».
- Вариации находятся по собственному названию, названию основного товара, своему ID и ID основного товара. Название вариации и её собственный ID сохраняются при добавлении.
- Поиск не зависит от регистра, «е/ё», вида дефисов и разделителей. Слова можно вводить в разном порядке: например, «НФГ 6.0 02» найдёт «НФГ-6,0-02».
- Учтены разные ключи массивов в ответах методов каталога. Если часть методов недоступна, приложение пытается получить товары через CRM API и показывает доступные результаты.
- Цена, полученная вместе с товаром, применяется. При отсутствии такой цены проверяется каталог цен, затем CRM API для того же ID. Цена основного товара не подставляется вместо цены вариации.
- Отсутствие цены, запрет чтения цен, ошибка API цен, некорректная или неоднозначная цена больше не блокируют добавление. Товар добавляется с ценой 0 и пометкой «Цена не указана — менеджер введёт её самостоятельно».
- Явная цена 0, возвращённая API, считается указанной ценой.
- Добавлено редактируемое поле «Базовая цена». После корректного ввода менеджером пометка снимается и расчёт обновляется. Ручная цена и пометка сохраняются в черновике и снимках.

Базовая цена участвует в формуле «Каталог»: базовая цена × К1 × К2 × К3. Формула «Excel» по-прежнему использует цену металла, вес и метизы.

Если API возвращает несколько цен без единственной подходящей базовой цены или цену только для диапазона количества, автоматически выбирать произвольную цену приложение не будет: менеджер получит ноль с пометкой и введёт цену вручную. Для товара без валюты цены используется валюта текущего КП. Полученная от API другая валюта не конвертируется автоматически.

## Установка обновления

1. Распакуйте архив и замените файлы размещённого приложения, включая новый `src/catalog.js`.
2. Откройте приложение в Битрикс24 и перезагрузите страницу с очисткой кеша (Ctrl+F5).
3. В выборе товара нажмите «Обновить каталог».
4. Проверьте поиск по названию основного товара, выбор вариации и добавление товара без цены. При необходимости введите цену в поле «Базовая цена».

Приложению нужен доступ на чтение каталога и CRM. Товары, которые портал не разрешает читать ни одним из доступных методов, получить невозможно; при частичной загрузке приложение показывает уведомление.

## Проверки

Регрессионные проверки на Node.js 20+:

```sh
node tests/catalog.test.mjs
```

Проверены загрузка 624 позиций с пагинацией, поиск вариаций по названию и ID основного товара, отсутствие лимита 500 совпадений, собственная цена вариации, отсутствие и ошибки цен, явный ноль, CRM API, резервное чтение из каталога и пересчёт ручной цены.

Интерфейс также проверен в Chromium с имитацией BX24: поиск, выбор вариации, пометка отсутствующей цены, ручной ввод, пересчёт и сохранение после перезагрузки. Все JavaScript-файлы прошли проверку синтаксиса. Проверка на реальном портале не выполнялась: доступ к нему в этой задаче не предоставлялся.
