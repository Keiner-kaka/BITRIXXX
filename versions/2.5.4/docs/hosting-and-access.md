# Где находится локальное приложение Битрикс24

«Локальное приложение» означает приложение, установленное для вашего портала. Это не означает, что его файлы обязательно находятся на персональном компьютере.

Проверьте URL обработчика в настройках установленного приложения:

- Если URL указывает на домен сервера или хостинга, файлы приложения находятся на этом сервере.
- Если URL ведёт на компьютер, который вы используете как веб-сервер, файлы находятся на этом компьютере и доступны другим сотрудникам, только пока он включён и доступен по сети.
- `localhost` и `127.0.0.1` всегда обозначают компьютер пользователя, который открывает приложение. Такой адрес не подходит для общего запуска с компьютеров коллег.
- По одному названию приложения и репозиторию GitHub определить ваш фактический сервер нельзя. GitHub-архив сам по себе не размещает приложение на вашем портале.

Открывать конструктор через локальное приложение Битрикс24 или вкладку сделки правильно: так официальный SDK получает контекст портала и авторизацию сотрудника.

## Где хранятся данные

| Данные | Место хранения |
|---|---|
| Файлы HTML, JS, CSS приложения | Сервер, указанный в URL обработчика |
| Выполнение интерфейса и расчёта | Браузер сотрудника |
| Текущие черновики и локальные сохранённые версии | localStorage конкретного браузера и профиля на конкретном компьютере |
| Общие версии КП | Диск Битрикс24, если настроена папка истории и сохранение подтверждено |
| Изображения подписей и загруженные справочники | Диск Битрикс24 |
| Привязки подписей к сотрудникам и общий шаблон КП | Общие опции приложения в Битрикс24 |
| Товары, перенесённые в сделку, и созданные документы | CRM Битрикс24 |

Запуск из Битрикс24 не переносит локальные черновики на сервер автоматически. На другом компьютере локальная история может отличаться. Для общей истории настройте папку Диска и права сотрудников.

Каждый сотрудник обращается к CRM и Диску со своими правами. Чтение сделки, связанного клиента, каталога, файлов подписей и создание документов нужно проверять под учётной записью самого сотрудника. Сбой запроса или тайм-аут сам по себе не доказывает отсутствие прав.
