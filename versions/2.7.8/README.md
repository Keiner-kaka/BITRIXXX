# Конструктор КП ЮЗМ 2.7.8

[Скачать установочный ZIP](https://github.com/Keiner-kaka/BITRIXXX/raw/refs/heads/release/v2.7.8/dist/yuzm-kp-bitrix-2.7.8.zip)

Изменение относительно 2.7.7: общий вес заказа и его запись в числовое поле сделки.

Общий вес заказа = сумма (вес одного изделия в кг × количество) по всем строкам. Коэффициенты, стоимость метизов и режим округления цены к весу не применяются. Сумма вычисляется десятичной арифметикой без округления до копеек. Итог показан рядом с суммой КП.

Произвольная строка использует прежнее поле «Вес,кг.». В каталожной строке добавлено компактное необязательное поле «Вес,кг.»; незаполненное поле учитывается как ноль. Цена каталожной позиции от веса не зависит. Формула стоимости произвольной позиции из 2.7.7 сохранена.

Вес изделия хранится в параметре weightKg каждой строки, включая каталожные. Он сохраняется в черновике, снимке расчёта и JSON на Диске и восстанавливается в поле соответствующей строки. У старого каталожного JSON без веса поле остаётся пустым. В снимке расчёта дополнительно вычисляется weightTotal; итог пересчитывается из весов строк после загрузки JSON.

Администратор задаёт «Настройки → Поле общего веса заказа → Код поля сделки для веса, кг», например UF_CRM_123456789, и сохраняет общие настройки. Нужен фактический код одиночного доступного для записи поля типа double на вашем портале. Для веса и доставки укажите разные поля. Пустой код отключает перенос веса. Сотрудники получают общую настройку установленного приложения при открытии конструктора или настроек.

После подтверждённого переноса строк приложение записывает общий вес в настроенное поле и перечитывает его. Генерация документа использует тот же перенос и записывает вес перед созданием документа. Предпросмотр и загрузка JSON в конструктор не записывают вес в CRM. Отдельная кнопка переноса стоимости доставки сохраняет прежнее назначение.

Запись веса проверяет формат кода, тип и доступность поля, ID сделки, успешность обновления и полученное значение. Вес не округляется до денежной точности. У поля CRM должна быть достаточная точность для вашего веса: если портал округлил значение или автоматизация его изменила, приложение сообщает о несовпадении. При ошибке после переноса товаров явно сообщается, что товары уже сохранены; автоматического повтора записи нет.

Установите содержимое ZIP поверх приложения и обновите страницу через Ctrl+F5. Администратор один раз сохраняет код поля веса, сотрудники обновляют страницу. Остальная логика 2.7.7 сохранена.

```sh
node --test versions/2.7.8/tests/*.test.mjs
python versions/2.7.8/tests/browser-weight.py
python versions/2.7.8/tests/browser-shared.py
```

Проверены суммирование всех строк с количеством, независимость от коэффициентов, JSON весов строк и восстановление итога, числовое поле CRM, запись и контрольное чтение без денежного округления, порядок переноса и генерации, отказ при недоступном поле и несовпадении результата. В Chromium проверены отображение общего веса, сохранение черновика и общая настройка поля администратора/сотрудника. Сохранены проверки цены, доставки, JSON и привязки документов. Проверки API выполнялись с имитацией, рабочий портал не проверялся.
