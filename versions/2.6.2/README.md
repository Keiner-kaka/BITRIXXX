# ЮЗМ · Конструктор КП 2.6.2

Один текущий расчёт на сделку, история реальных документов из Битрикс24 и единый поиск товаров с виртуальной прокруткой.

## Активные товары — 2.6.2

Конструктор запрашивает только активные товары: active=Y в catalog.product.list / sku.list / offer.list и ACTIVE=Y в crm.product.list. Фильтр сохраняется при совместимом чтении свойств 108/110/112. Дополнительно явно неактивные ответы исключаются до построения индекса; поиск по названию, характеристикам или ID их не возвращает.

При выборе активность запрашивается повторно через get. Если портал поддерживает только list, для выбранного ID выполняется свежий запрос с фильтром активности, вместо доверия прежнему кешу. Если товар деактивировали после загрузки каталога, добавление блокируется с сообщением. Новая генерация и перенос расчёта в сделку также проверяют товары до записи в CRM.

Текущие строки старых черновиков и сделок автоматически не удаляются; при обнаружении деактивированной позиции её следует заменить перед новой генерацией. Уже созданные документы остаются в истории. Свойство 114 по-прежнему игнорируется.

После деактивации товаров на портале нажмите «Обновить каталог» в поиске или перезагрузите приложение: фильтрация в памяти не делает REST-запрос на каждое нажатие клавиши. Если API не возвращает поле активности, используем результат запроса active=Y / ACTIVE=Y, сохраняя совместимость с прежними порталами.

Важно: отключить нужно активность самих товаров. Деактивация одного раздела или перенос в раздел «Архив» не являются деактивацией карточек. По разделам приложение в этой версии не фильтрует. Активность вариации проверяется по её собственной карточке.

## Характеристики в каталоге — 2.6.1

Для инфоблока 24 читаются только числовые свойства:

| ID | Код | Показ в списке |
|---|---|---|
| 108 | DIAMETRMM_FMZJ0M | Диаметр, мм |
| 110 | TOLSHCHINA_STENKIMM_HYFNS6 | Стенка, мм |
| 112 | VESKG_YW0GYI | Вес, кг |

Свойство 114 «базовая цена» игнорируется: не запрашивается, не отображается и не участвует в расчёте. В строках поиска: название, затем стенка/диаметр/вес, затем «Подробнее» и кнопка добавления. «Подробнее» открывает полное название, ID и характеристики отдельным окном, сохраняя фиксированную высоту виртуальной строки.

Характеристики находятся только в памяти текущей страницы и индексе поиска. Они не записываются в localStorage, черновик, JSON расчёта, товарные строки сделки или данные для шаблона. Каталожный вес не заполняет расчётный вес строки. В КП уходит исходное имя товара без добавленных интерфейсом характеристик; если пометки уже внесены в само NAME, приложение их не вырезает — для чистого КП исправьте NAME в каталоге.

Поиск учитывает значения и подписи характеристик. Например, `диаметр 133`, `стенка 3,5`, `вес 28` и `ЗФ диаметр 159`; запросы с названием характеристики сравнивают её числовое значение точно. Обычный поиск по словам и ID сохранён.

Свойства запрашиваются в select методов catalog.product.list / sku.list / offer.list вместе со страницами каталога 24. Если портал отвергает эти поля или полностью игнорирует их, используется совместимый crm.product.list с PROPERTY_108/110/112. Отдельных запросов get на каждую позицию при просмотре нет. Поиск и «Подробнее» не обращаются к API. Кнопка обновления каталога перечитывает данные.

Пустые, недоступные и некорректные значения не превращаются в нули. Ноль, явно возвращённый API, показывается. Характеристики вариаций не наследуются от основного товара, чтобы не показывать неверный диаметр/вес. Если свойства заполнены только у родителя, у вариации их не будет. ID свойств привязаны к этому порталу: при переносе на другой портал требуется изменить конфигурацию в src/catalog.js.

## Что изменилось в 2.6.0

- Убраны варианты КП, создание копий и кнопка сохранения версии.
- В браузере автоматически сохраняется только один текущий черновик сделки. Нет локальной истории и массивов сохранённых версий. Предпросмотр не создаёт запись истории.
- История загружается из генератора документов CRM по ID сделки. В ней только уже созданные документы: название, дата, ссылки DOCX/PDF и обновление готовности. Включаются также документы этой сделки, созданные с другого компьютера. Для истории требуется право просмотра документов.
- Ошибка генерации не создаёт запись истории. После успешного ответа API документ появляется в списке и может быть получен заново с сервера после перезагрузки или очистки локального черновика.
- В строках расчёта больше нет select с полным каталогом. Нажатие на название товара или «Выбрать из каталога» открывает один общий диалог; он же используется для добавления и из настроек.
- В диалоге одно поле поиска по названию, вариации, названию основного товара и ID. Числовой запрос находит ID и числовые названия. `#123` или `id:123` ограничивают поиск ID товара и связанных вариаций.
- Виртуальный список создаёт в DOM только видимые строки с небольшим запасом. Поиск выполняется по заранее нормализованному индексу; каталог повторно не запрашивается при каждом вводе. Поддержаны прокрутка, стрелки, PageUp/PageDown, Home/End и добавление с клавиатуры.

## Обновление и переход со старой версии

1. Замените файлы приложения содержимым ZIP, сохранив используемый серверный обработчик. Важно загрузить новые модули `src/draft-store.js` и `src/virtual-list.js`.
2. Перезагрузите приложение с очисткой кеша (Ctrl+F5).
3. При первом запуске из прежних данных браузера переносится выбранный текущий черновик вместе с его справочниками и ручными полями. Старые локальные варианты, копии, версии и кэш документов удаляются из записей приложения; остаётся один черновик на сделку.
4. История документов заполняется данными из CRM. Старые JSON-файлы на Диске не читаются как история и не удаляются. Сформированные ранее документы в CRM не изменяются.

Текущий черновик по-прежнему локален конкретному браузеру; серверная история документов общая для доступной сотруднику сделки. Настройка папки сохранённых JSON-версий больше не используется.

Пройдены 48 регрессионных тестов и проверка синтаксиса всех JavaScript-модулей. В Chromium с имитацией BX24 проверены:

- скрытие неактивных товаров и вариаций, фильтр активности обоих семейств REST, отказ при деактивации после загрузки, сохранение старых строк без автоматического удаления;
- отображение диаметра/стенки/веса, одинаковые названия с разными характеристиками, поиск без дополнительных REST-запросов, окно подробностей, узкий экран, отсутствие характеристик в черновике и игнорирование свойства 114;
- переход с двух локальных вариантов на выбранный текущий черновик без сохранённых версий;
- сохранение коэффициентов более старых черновиков;
- загрузка 50 004 позиций и не более 14 строк каталога в DOM, переход к концу списка с клавиатуры, поиск, добавление и замена товара через один диалог;
- получение документов из CRM, фильтрация другой сделки, создание документа, отсутствие записей истории при предпросмотре и неудачной генерации;
- повторная загрузка истории после очистки localStorage, обработка ошибок чтения документов;
- сохранение срока исполнения, условий самовывоза, контактов менеджера и цен при генерации DOCX.

Реальный портал в этой задаче не предоставлялся. На нём отдельно проверяются права сотрудника и доступность методов CRM. Виртуализация ограничивает число DOM-строк; первоначальное чтение большого каталога всё ещё зависит от пагинации, сети и лимитов REST Битрикс24.

Документация метода истории: [crm.documentgenerator.document.list](https://apidocs.bitrix24.ru/api-reference/crm/document-generator/documents/crm-document-generator-document-list.html).
