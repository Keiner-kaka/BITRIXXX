# Конструктор КП ЮЗМ 2.7.5

Исправление 2.7.4: общие настройки сотрудников и доступ к шаблонам при создании документов.

[Скачать установочный ZIP](https://github.com/Keiner-kaka/BITRIXXX/raw/refs/heads/release/v2.7.5/dist/yuzm-kp-bitrix-2.7.5.zip)

## Причины и исправления

В 2.7.4 ID папки JSON, поля сделки, сопоставления оплаты/доставки, типовые формулировки и округление сохранялись только в localStorage браузера. Теперь администратор сохраняет их через app.option.set в ключ yuzmQuoteConstructorSettings. Сотрудники читают через app.option.get при подключении конструктора и открытии настроек. ID сделки и черновик остаются индивидуальными. Старые настройки браузера сотрудника не заменяют опубликованные общие настройки. Если общие настройки ещё не созданы, у администратора остаются значения его браузера для первой публикации; сотрудник видит сообщение, что требуется сохранение администратором.

Настройки общие в рамках одного установленного приложения и одного портала. Разные установленные приложения имеют разные app.option. После изменения настроек сотрудники должны обновить страницу либо открыть настройки заново. Шаблон остаётся в прежнем ключе yuzmQuoteTemplateId, подписи сотрудников не перезаписываются. Общие настройки и выбранный новый шаблон публикуются одним app.option.set с контрольным чтением. В настройки не включаются содержимое сделки, строки расчёта или произвольные ключи. Сохранение администратором проверяет редакцию: если другой администратор успел её изменить, требуется перечитать настройки. Битрикс не предоставляет транзакционную блокировку записи app.option.

В 2.7.4 при открытии конструктора сотрудник вызывал crm.documentgenerator.template.list, а при генерации — template.get. Эти методы требуют права изменения шаблонов генератора, которого у обычного сотрудника может не быть. Теперь список загружает и шаблон выбирает только администратор. Сотрудник читает сохранённый ID, перед генерацией сверяет его с общим ID и использует crm.documentgenerator.document.add. Права создания документа, доступ к шаблону и его применимость проверяет Битрикс24. Право редактирования шаблонов сотруднику для работы конструктора выдавать не требуется.

Это не выдаёт дополнительных прав сотруднику на портале: для создания документа всё равно нужны соответствующая роль генератора, доступ к сделке, выбранному шаблону и папке Диска. Если document.add отклонён после переноса строк, приложение сообщает, что товары уже перенесены. JSON, загрузка с подтверждением, привязка JSON к ID документа, формула и подтверждение переноса сохранены.

## Обновление

1. Замените файлы размещённого приложения содержимым ZIP 2.7.5. Обновление должно быть установлено по адресу приложения, которым пользуются все сотрудники. Не создавайте отдельное установленное приложение каждому сотруднику.
2. Войдите администратором в конструктор. Нажмите Ctrl+F5. В настройках проверьте ID папки, поля, соответствия, формулировки, округление и общий шаблон, затем один раз нажмите «Сохранить настройки».
3. Убедитесь, что появилось сообщение «Общие настройки сохранены в Битрикс24 и доступны сотрудникам этого приложения».
4. Сотрудники обновляют конструктор через Ctrl+F5. Общие параметры у них доступны только для чтения; выбирать ID сделки и редактировать расчёт можно как прежде.
5. Проверьте генерацию на тестовой сделке. При DOCGEN_ACCESS_ERROR проверьте роль сотрудника в генераторе документов и доступ к выбранному шаблону; при ошибке списка шаблонов у администратора — его право изменения шаблонов. Публичную ссылку на папку создавать не нужно.

Если сохранить настройки без подключения к Битрикс24, они сохранятся только в браузере; интерфейс явно это сообщает. Неуспешная запись либо неподтверждённое контрольное чтение не выдаются за успешное общее сохранение.

## Проверки

```sh
node --test versions/2.7.5/tests/*.test.mjs
python versions/2.7.5/tests/browser-shared.py
python versions/2.7.5/tests/browser-load.py
```

Проверены публикация администратором и чтение сотрудником в независимых браузерных контекстах, замена устаревшего локального ID папки, получение настроек новым браузером, ограничения редактирования, отсутствие template.list/get у сотрудника, создание документа по общему ID, смена шаблона до генерации, конфликт редакций, отказ API, повреждённый JSON и неподтверждённое чтение после записи. Прошли проверки загрузки JSON и привязки к документу, синтаксис модулей, целостность архива и его соответствие исходникам. API в проверках имитируется; на рабочем портале новая версия не проверена.
