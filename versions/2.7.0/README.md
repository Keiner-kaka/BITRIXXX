# ЮЗМ · Конструктор КП 2.7.0

## Произвольные строки

Справа от «Добавить изделие» находится компактная кнопка «+ Добавить поле». Она создаёт строку с пустыми наименованием и ценой. Менеджер вводит название, цену за единицу и количество; коэффициенты, покрытие и срок исполнения работают так же, как у каталоговых изделий. Название и цена обязательны. Явно введённый ноль допустим; пустая цена блокирует предпросмотр и генерацию.

Произвольная строка входит в таблицу DOCX/PDF и общий итог КП, но не создаёт товар каталога и не передаётся в товарные позиции сделки. Смешанный КП записывает в CRM только каталоговые строки. Если КП состоит только из произвольных строк, генерация вообще не меняет товары сделки; кнопка переноса товаров недоступна.

Сумма документа включает произвольные строки. Сумма товарных позиций CRM их не включает, поэтому эти суммы могут различаться. Уже созданные документы и текущие черновики не удаляются; произвольные строки сохраняются в одном локальном черновике текущего браузера.

## Цена в поиске и редактирование

В карточке товара справа от названия показана цена каталога, рядом ниже — все заполненные характеристики, включая цену МК и текстовые размеры. Длинные значения полностью доступны через «Подробнее». Цена запрашивается асинхронно для видимых строк, пакетами до 50 ID, и кешируется в памяти страницы. Для всего каталога цены при открытии не запрашиваются. Пока API отвечает, показано «Загрузка цены…». При недоступной цене выводится 0 и «цена не указана»; реальная нулевая цена не получает эту пометку. При выборе цена и активность проверяются заново.

В строке расчёта вместо постоянного поля ввода показана изменяемая строка с ценой каталога (для существующих товаров сделки — сохранённая цена сделки). Двойное нажатие на цену, Enter с клавиатуры или значок карандаша открывают редактирование. Enter или уход фокуса сохраняют ввод; Escape возвращает прежнее значение. Для произвольной строки ввод цены виден сразу и обязателен.

Свойство 114 «базовая цена» полностью игнорируется. Цена товара берётся из штатных методов каталога/CRM. Характеристики не дописываются к наименованию КП; если пометки уже находятся в самом NAME, приложение их не вырезает.

Настройки ID, кодов, типов и подписей находятся в `src/catalog.js`. Все перечисленные свойства запрашиваются вместе со страницами каталога, доступны в поиске и подробностях. Навигационные характеристики существуют только в памяти страницы. В локальный черновик и расчёт попадают лишь сумма выбранных метизов, её источник и состояние флажка, поскольку они влияют на итог. Геометрия, вес, фланец и место кронштейна в строки КП и товарные позиции CRM не передаются.

## Метизы из свойства 116

У каждой позиции есть чекбокс «Метизы». При новом выборе товара он автоматически включается только для основного раздела **44** инфоблока **24**. Для остальных разделов и произвольных строк он по умолчанию выключен; менеджер может включить его сам. Вложенных разделов нет, дополнительные ID не включены. Правило определяется по `iblockSectionId` / `SECTION_ID`, без поиска слов «Опора» или марки изделия. Настройка раздела находится в `src/fasteners.js`.

Стоимость берётся из свойства **116 — TSENA_MK_RUB_3RS0SE** выбранного товара, на одно изделие. Если значение получено, показывается его сумма из каталога без отдельного редактируемого ввода. Явный ноль считается указанной ценой.

Если значение пустое, недоступное или некорректное, при включённом чекбоксе появляется поле **«Укажите стоимость метиз.»**. Оно отсутствует по умолчанию и скрывается при отключении чекбокса. Менеджер вводит неотрицательную сумму, включая явный 0, либо отключает метизы. Пустое обязательное значение блокирует предпросмотр и генерацию. Для произвольной строки действует такой же ручной ввод после включения метизов.

```text
Цена единицы = (цена каталога/менеджера + включённые метизы) × К1 × К2 × К3
Сумма строки = цена единицы × количество
```

Стоимость из свойства 116 авторитетна: прежняя ручная сумма не подменяет полученную цену МК. Метизы прибавляются до всех коэффициентов и умножаются на количество вместе с ценой изделия. Отдельной товарной позиции или отдельной строки метизов в КП не создаётся.

Статическая таблица из XLSX и сопоставление по наименованию удалены. Нет отдельных запросов на каждую строку при просмотре каталога. При выборе цена товара, активность, раздел и МК читаются заново; если современный get не вернул нужные поля, перечитывается только выбранный ID через активный список. Отдельного чтения дерева разделов и дополнительных прав администратора не требуется.

Для вариации без собственного раздела допускается подтверждённый раздел основного товара из текущего каталога. Цена МК от родителя не наследуется: если у выбранной вариации нет свойства 116, используется ручной ввод. Обновление каталога перечитывает список и его характеристики. Повторный выбор товара подставляет актуальную цену МК в строку; уже введённый расчёт не пересчитывается неожиданно в фоне.

Свойство 116 задано в RUB. Если валюта КП другая, автоматической конвертации нет: при включённых метизах менеджер вводит сумму в валюте КП. Старые строки сделки/черновика не получают надбавку при загрузке, как было согласовано ранее; для актуальных свойств нужно выбрать товар из каталога заново. Условия по крепежу в шапке остаются редактируемым текстом: проверяйте, что они соответствуют выбранным флажкам.

## Покрытия и упрощение настроек

Добавлено «Нестандартное покрытие». После выбора появляется обязательное текстовое поле; введённый вариант передаётся в КП. Название покрытия не меняет цену само по себе, коэффициент К3 вводится отдельно. Обычные покрытия и RAL сохранены.

Режим Excel, поля цены за кг/расчётного веса и импорт справочников цен металла удалены. Также удалён импорт JSON-наименований покрытий с Диска и компьютера. Встроенный список находится в `data/coatings.example.json`; это часть поставки, а не пользовательский импорт. JSON-экспорт самого расчёта сохранён.

При переходе со старого черновика Excel строки сохраняются, но генерация блокируется до явного обновления каталоговой/ручной цены. Это предотвращает незаметный переход на другую формулу. Старые названия покрытий, которых нет во встроенном списке, переносятся в «Нестандартное покрытие».

## Установка и сохранённые возможности

В установочном ZIP `index.html`, `styles.css` и папки `src`/`data` расположены непосредственно в корне. Загрузите ZIP в установщик Битрикс24 либо замените все файлы на своём хостинге, включая новый `src/fasteners.js`, затем обновите страницу с очисткой кеша (Ctrl+F5).

Сохранены: фильтр активных товаров и повторная проверка активности, вариации, виртуальный список, история созданных документов CRM, подпись ответственного, сроки исполнения, самовывоз, документы к поставке, общий шаблон и один текущий черновик без версий/копий.

71 автоматический тест проверяют расчёт, метизы до коэффициентов, обязательные свободные поля, нестандартное покрытие, разделение КП/CRM, только произвольные строки без очистки сделки, цены пакетами, активность, свойства, вариации, подписи и историю. Синтаксис всех JavaScript-модулей проверен.

В Chromium с имитацией BX24 проверены добавление/сохранение произвольной строки, обязательная цена, ручная цена через двойное нажатие/Enter/Escape, свойство 116, раздел 44, флажок для других товаров, ручная сумма при пустом МК, строковые характеристики, отключение надбавки, цены в каталоге, поиск без повторного чтения кешированных цен, мобильный экран, смешанная и полностью произвольная генерация, переход со старых данных, история и каталог с 50 тысячами позиций. Реальный портал не предоставлялся.

Виртуализация ограничивает DOM, цены читаются только для видимых строк. Первоначальная загрузка самого каталога по-прежнему зависит от числа страниц и лимитов REST. Одновременная запись товарных позиций и создание документа не являются транзакцией Битрикс24: если создание документа завершилось ошибкой после записи, приложение сообщает, что товары уже перенесены.
