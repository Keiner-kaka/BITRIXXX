# ЮЗМ · Конструктор КП v2.7.0-integration.1

Доработка существующей v2.7.0 для облачного Bitrix24. Формулы, активный каталог, метизы, подписи менеджеров и генератор DOCX сохранены.

[Скачать установочный ZIP](https://github.com/Keiner-kaka/BITRIXXX/raw/refs/heads/main/dist/yuzm-kp-bitrix-2.7.0-integration.1.zip) · [Технический отчёт](docs/technical-report.md)

Опубликовано в GitHub 24 октября 2026 года. Обновление на портале Bitrix24 устанавливается отдельно.

## Новое поведение

- Первичные поля сделки назначаются динамически в `admin.html`: даты, клиент, ответственный, оплата и доставка. Админка работает в том же установленном приложении и не создаёт новую вкладку CRM.
- Все строки КП, включая произвольные, передаются в товары сделки. Товары каталога автоматически не создаются.
- Единое подтверждённое сохранение включает документ, полный состав товаров, сумму, массу, доставку и JSON последнего КП. Ошибка любого этапа не считается успехом.
- Журнал операции и Web Locks предотвращают повтор документа при двойном нажатии и позволяют продолжить частично выполненную запись. Неоднозначный результат создания требует сверки истории.
- Ручная кнопка восстановления проверяет JSON, версию алгоритма, SHA-256, сделку и документ, затем запрашивает подтверждение и пересчитывает данные штатным калькулятором.
- Локальный черновик сделки сохраняется независимо. Автоматического восстановления из CRM при открытии нет.
- Тексты КП хранятся в JSON на Диске, редактируются и публикуются новой версией того же файла. Фактические тексты сохраняются внутри снимка расчёта.
- Последнее сформированное КП имеет статус `generated`; согласование клиентом не устанавливается.

## Коэффициенты и масса

```text
Цена единицы = (базовая цена + включённые метизы) × К1 × К2 × К3
Сумма строки = цена единицы × количество
К1 — скидка; К2 — доставка; К3 — покрытие или краска.
```

Прежние правила округления сохранены. При несовместимости суммы строк и округлённой цены единицы CRM сохранение требует явно выбрать округление цены единицы.

Масса не участвует в цене. Для нового каталожного товара она берётся из свойства 112; для старых строк и работ вводится явно, включая 0. Доставка К2 выделяется разницей двух штатных расчётов: с текущим К2 и с К2 = 1. Отдельная платная доставка оформляется произвольной строкой с флажком «Отдельная доставка».

## Сохранённые возможности v2.7.0

Активные товары и вариации, проверка активности перед записью, поиск по названию/ID/свойствам, виртуальный список и пакетные цены для видимых строк. Свойства инфоблока 24: 108 — диаметр, 110 — стенка, 112 — масса, 116 — цена МК, 118 — фланец, 120 — межцентр, 122 — кронштейн, 124 — срезы. Свойство 114 не используется.

Метизы автоматически включаются только при новом выборе товара основного раздела 44. Цена свойства 116 добавляется до всех коэффициентов; при её отсутствии требуется ручная сумма, включая явный 0. Старые строки не получают надбавку автоматически. Не-RUB требует ручной цены метизов без скрытой конвертации.

Сохранены редактирование базовой цены, произвольные строки с обязательными названием и ценой, нестандартное покрытие, RAL, сроки исполнения, самовывоз, подпись ответственного и история документов CRM. Прежний DOCX-шаблон не заменяется JSON-файлом текстов.

## Проверки

Из этой папки:

```sh
npm test
npm run check
```

101 тест версии охватывают прежние сценарии и 30 новых проверок интеграции. Из корня репозитория `npm test` запускает также 34 проверки исходного прототипа — всего 135. Корневая проверка синтаксиса охватывает 21 модуль.

Браузерная проверка с имитацией BX24:

```sh
python3 -m http.server 8080 --bind 127.0.0.1
# Во втором терминале; нужны Playwright и Chromium:
python3 tests/browser-integration.py
```

Проверены интерфейс менеджера, поля/массивы, подписи коэффициентов, отмена, полное сохранение произвольных строк, ручное восстановление, независимый черновик, частичный повтор, узкий экран, админка, публикация JSON и запрет записи менеджеру.

На реальном портале проверка не завершена: ссылка на сделку 718 доступна среде только как страница входа. Настоящие права, CORS, генерация DOCX/PDF и роботы требуют приёмки в авторизованном приложении.
