# Отчёт: сохранение общих настроек ЮЗМ

Версия: **2.7.0-integration.2**. Дата: **24 октября 2026 года**, Europe/Moscow.

## Исправленная причина

Ранее «Сохранить общие настройки» запускала общую проверку: список `methods`, генератор документов и чтение JSON Диска. Отсутствие метода в списке или ошибка файла блокировали запись сопоставлений.

Список `methods` не подтверждает фактическую доступность отдельного вызова. В новой версии ни сохранение, ни диагностика от него не зависят. Генератор проверяется прямым `crm.documentgenerator.template.list`.

## Сохранение

Сохранение проверяет структуру, обязательные назначения, формат ID, существование выбранных полей, их типы, доступность записи в поля результатов и отсутствие дубликатов. Метаданные полей перечитываются перед сохранением. После проверки выполняются только `app.option.set` с прежним ключом `yuzmIntegrationConfig` и контрольный `app.option.get` со сравнением результата.

Чтение/обновление JSON и доступность генератора не участвуют в этом сценарии. Сохраняется административная проверка в приложении; `app.option.set` также ограничен правами Bitrix24. Другие ключи, включая DOCX-шаблон и подписи, не записываются и не очищаются.

`revision` получает новое ISO-время при каждой записи. Последовательные записи одной сессии получают разные значения даже внутри одной миллисекунды. Отсутствующий ключ отличается от существующей конфигурации: значения по умолчанию явно помечаются как несохранённые.

## Статусы формы

- Изменение настроек: **«Есть несохранённые изменения»**.
- Запись и контрольное чтение подтверждены: **«Настройки сохранены»**, подтверждённая редакция и время по Москве.
- Запись отправлена, но контрольное чтение завершилось ошибкой или вернуло другой результат: **«Запись отправлена, подтверждение сохранения не получено»**. Введённые значения остаются в форме.
- Неоднозначный таймаут отправки также не выдаётся за подтверждённое сохранение.
- Ключ ещё не создан: **«Общие настройки ещё не сохранены»**.
- Перечитывание заменяет форму сохранёнными значениями только после подтверждения потери несохранённых/неподтверждённых изменений.

Удалённое поле показывается как недоступное с прежним кодом. Ошибка проверки или записи не сбрасывает введённые соответствия. Обычный менеджер может прочитать сохранённые настройки и запустить диагностику, но элементы изменения и кнопки записи ему недоступны.

## Диагностика

Проверки выполняются независимо. Ошибка одного компонента не отменяет остальные и не изменяет статус подтверждённой записи настроек.

| Компонент | Фактическая проверка |
|---|---|
| Поля сделки | `crm.deal.fields`, `crm.deal.userfield.list`, существование, типы, назначения |
| Генератор | Прямой `crm.documentgenerator.template.list`, включая обработку страниц ответа |
| Тексты | `disk.file.get`, фактическое чтение содержимого и проверка схемы JSON |
| Папка | `disk.folder.get`, `disk.folder.getchildren`, если ID задан |
| Дополнительные файлы | `disk.file.get` для каждого заданного ID; отдельные результаты при нескольких файлах |

Диагностика не вызывает `app.option.set`, создание документов, обновление/загрузку файлов, запись товаров или полей сделки. Успешное чтение прямо сопровождается указанием, что право записи не проверялось.

Ошибки отображают действие, метод, код и безопасное описание REST. URL, секретные части вебхуков, OAuth-токены, `Bearer` и подписанные адреса скрываются до вывода. Для ошибок структуры/формата показывается ошибка проверки, без выдуманного REST-кода.

## Совместимость и состав изменений

Изменены `admin.html`, `src/admin.js`, `src/integration-config.js` и обработка безопасных ошибок в `src/bitrix.js`. Добавлены `src/integration-diagnostics.js`, `src/rest-errors.js` и тесты сохранения настроек.

Ключи и схема конфигурации сохранены. Файлы калькулятора, доставки/JSON-снимков, восстановления/сохранения КП, каталога и подписей не менялись относительно предыдущей публикации. Новых интеграций, полей CRM и товаров нет. Предварительные проверки и обработка частичных операций сохранения КП сохранены.

## Проверки

**151 автоматический тест проходит**, включая 16 новых проверок сохранения/диагностики. Из них 117 относятся к актуальному приложению и 34 — к исходному прототипу. Проверен синтаксис 23 модулей репозитория, в автономном приложении — 19.

Браузерные сценарии Chromium с имитацией BX24 подтвердили:

1. Сохранение без вызова `methods`, генератора или Диска, включая случай работающего метода, отсутствующего в списке.
2. Сохранение и повторное открытие сопоставлений и редакции через `app.option`.
3. Независимые ошибки генератора, Диска и некорректного JSON; диагностическое чтение не меняет настройки.
4. Новый `revision`, признак несохранённой формы, неподтверждённое контрольное чтение, сохранение введённых значений.
5. Отмена/подтверждение перечитывания; проверка удалённого поля без сброса формы.
6. Чтение общих настроек менеджером и запрет административных записей.
7. Явный статус отсутствующей конфигурации; значения по умолчанию не обозначаются сохранёнными.
8. Сохранённые сценарии расчёта, товаров, JSON, ручного восстановления и повторов после частичного сбоя КП.

Тесты используют имитацию REST. Новая версия не устанавливалась на реальный портал; реальная приёмка выполняется администратором после замены файлов. Старый установочный ZIP `2.7.0-integration.1` сохранён, новый ZIP выпускается отдельно.

## Установка

Обновите файлы того же приложения из ZIP `2.7.0-integration.2` и очистите кеш страницы. Повторно создавать интеграцию или назначения не нужно. Откройте админку, измените тестовое назначение, сохраните и перечитайте его; затем отдельно выполните диагностику. При ошибке текстов настройки должны остаться подтверждённо сохранёнными, а причина ошибки — появиться в строке компонента «Файл текстов».
