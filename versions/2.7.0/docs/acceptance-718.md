# Приёмка на тестовой сделке №718

Цель: https://yzm-krd.bitrix24.ru/crm/deal/details/718/

Статус на 23.10.2026: проверка в авторизованном портале **не выполнена**. Из среды разработки GET возвращает HTTP 200 со страницей «Войти в Битрикс24» и формой авторизации. Учётные данные, сессия браузера и OAuth-контекст этого портала среде не предоставлены. Реальная сделка не изменялась. Браузерные проверки использовали имитацию API и не подтверждают реальные права, CORS или поведение роботов.

Протокол после размещения обновления:

1. Администратором открыть существующее приложение, выбрать реальные поля и файл текстов, нажать проверку/сохранение конфигурации. Проверить наличие методов и чтение JSON из iframe; при необходимости настроить HTTPS-прокси.
2. Сохранить исходный состав товаров тестовой сделки для сверки. Открыть её вкладку конструктора и проверить ID 718, клиента, ответственного, даты, оплату, доставку, массивы/списки и подпись.
3. Добавить каталожную и произвольную строку. Уточнить массу. Проверить К1/К2/К3, метизы и покрытие. Убедиться, что изменения формы не записывают CRM.
4. Сформировать предпросмотр, отменить подтверждение и убедиться, что документ, товары и JSON не менялись.
5. Подтвердить сохранение. Проверить историю документа, DOCX/PDF, полный состав товаров, сумму, массу, доставку и JSON. Проверить документ/сделку/номер/статус `generated` в JSON. Убедиться, что согласование не выставлено.
6. Сделать несохранённую локальную правку, обновить вкладку: локальный черновик должен сохраниться независимо от JSON сделки. Отменить ручное восстановление — правка должна остаться. Подтвердить восстановление — расчёт и фактические тексты должны вернуться, суммы должны пересчитаться.
7. Опубликовать новую редакцию текстов с тем же ID файла. Перечитать варианты, выбрать новую формулировку и создать следующее КП. Старый документ сохраняет прежний текст. Последний JSON обновляется только при следующем успешном сохранении.
8. Проверить ошибки доступа на отдельной тестовой конфигурации: приложение не должно сообщать об успехе при частичной записи. Повтор должен использовать уже созданный документ. Потерю ответа на создание документа проверять только контролируемым тестовым транспортом, чтобы не создавать случайные копии на портале.
9. Другим менеджером проверить запрет записи общих настроек, права чтения шаблонов/подписи и доступ к сделке. Проверить, что существующая автоматизация CRM не считает генерацию согласованием заказа.

Фиксировать результат каждого пункта, ID созданных документов, версию конфигурации, назначенные поля и фактический способ чтения Диска. Не включать токены и URL скачивания с авторизацией в отчёт.
