# Карта изменений интеграции v2.7.0

Исходная проверка: `node --test versions/2.7.0/tests/*.test.mjs` — 8 файлов, 71 сценарий внутри файлов; корневые `npm test` и `npm run check` также проходят. Корневые npm-команды ранее не охватывали v2.7.0.

| Компонент | Изменение |
|---|---|
| calculator.js, catalog.js, fasteners.js | Сохранить действующие формулы, поиск, активность и метизы |
| integration-config.js | Динамические поля, типы, списки, массивы, app.option одной интеграции |
| text-templates.js, server.mjs | Версионируемый JSON Диска; проверка чтения, CORS и серверный транспорт |
| quote-snapshot.js | Версии схемы/алгоритма, фактические тексты, SHA-256, проверяемое ручное восстановление |
| quote-save.js | Предварительные проверки, подтверждение замены, журнал операции, безопасный повтор, проверка результата |
| bitrix.js | Разделить подготовку/создание документа; переносить все строки, включая произвольные; проверять ответы |
| app.js, index.html, draft-store.js | Загрузка первичных полей; самостоятельный локальный черновик; явное восстановление; масса и выделение доставки |
| admin.html, admin.js | Отдельная страница той же интеграции без новой вкладки; настройки, диагностика, подписи и публикация JSON |
| tests, документация | Регрессия и сбои интеграции, инструкция, протокол тестовой сделки |

В исходной версии масса намеренно не участвовала в цене, а коэффициенты не имели машинно заданного назначения «доставка». Масса добавляется как независимая характеристика. Пользователь уточнил: К1 — скидка, К2 — доставка, К3 — покрытие или краска. В интерфейсе добавлены эти подписи; по умолчанию для доставки назначен К2, формула цены не меняется. Отдельную платную доставку можно добавить обычной произвольной строкой с признаком доставки.

Операции REST не являются транзакцией. Перед записью требуется подтверждение текущих строк. Неоднозначный таймаут создания документа запрещает автоматический повтор создания; журнал позволяет вручную привязать найденный документ после проверки сделки и маркера операции. Запись не меняет статус согласования и не запускает производство.

Проверка реального облачного портала зависит от установленного приложения и тестовой сделки; подмена этой проверки имитацией API недопустима.
