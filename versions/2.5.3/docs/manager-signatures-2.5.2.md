# ЮЗМ · Конструктор КП 2.5.2

Добавлен блок ответственного менеджера по предоставленному образцу: слева приветствие, должность, почта и телефон; по центру изображение подписи; справа ФИО. Исправления каталога и вариаций из версии 2.5.1 сохранены.

## Обновление приложения

Распакуйте ZIP и замените файлы размещённого приложения, включая `src/manager.js` и `src/catalog.js`. Перезагрузите приложение с очисткой кеша (Ctrl+F5).

## Подготовка шаблона DOCX

В комплекте есть [готовый блок подписи](templates/manager-signature-block.docx). Откройте его в Word и скопируйте всю таблицу из трёх ячеек в конец своего шаблона КП. Границы таблицы не печатаются. Сохраните и обновите шаблон в генераторе документов Битрикс24; при необходимости выберите его в настройках приложения.

Поля блока:

| Поле | Содержимое |
|---|---|
| `{YuzmManagerPosition}` | Должность из профиля ответственного |
| `{YuzmManagerEmail}` | Почта из поля EMAIL профиля |
| `{YuzmManagerPhone}` | Рабочий телефон WORK_PHONE |
| `{YuzmManagerName}` | Фамилия, имя и отчество |
| `{YuzmManagerSignature}` | Изображение индивидуальной подписи |

Поле изображения нельзя вставлять обычным текстом. В приложенном DOCX уже есть прозрачное изображение-заполнитель с кодом `{YuzmManagerSignature}` в замещающем тексте. Если оформляете блок самостоятельно, вставьте любую картинку в нужную ячейку, задайте ей размер и в Word укажите этот код в «Замещающий текст». Генератор заменит картинку подписью менеджера.

## Однократная настройка каждого менеджера

1. В профиле сотрудника Битрикс24 заполните ФИО, должность, почту и рабочий телефон.
2. Загрузите изображение его подписи на Диск Битрикс24. Поддерживаются PNG и JPEG до 2 МБ; предпочтителен PNG с прозрачным фоном. Сотрудникам, создающим КП, нужен доступ на чтение этого файла.
3. Администратором откройте приложение в сделке, где этот менеджер указан ответственным.
4. Разверните «Подпись менеджера». Введите **ID файла на Диске**, затем нажмите «Сохранить подпись сотрудника».
5. Проверьте контакты и изображение в блоке. Повторите настройку для остальных сотрудников в их сделках.

ID файла — именно ID объекта Диска, возвращаемый методами `disk.file.get` / `disk.folder.getChildren`, а не ID пользователя и не ID вложения. Настройка сохраняется в общих опциях приложения отдельно для ID каждого сотрудника и доступна всем менеджерам приложения. Изменить её может администратор. Чтобы удалить привязку, очистите поле и сохраните.

ФИО и контакты берутся по ASSIGNED_BY_ID сделки. Вариант КП сохраняет ID ответственного и ID изображения. При смене ответственного старые контакты и изображение не переходят новому сотруднику. Кнопка «Подставить данные ответственного» обновляет текущий черновик; перед сохранением версии профиль также проверяется повторно. Правки контактов вручную сохраняются для прежнего ответственного и сбрасываются при его смене.

Если ответственный изменился после сохранения версии, создание нового документа из старой версии останавливается до переноса товаров в CRM. Обновите данные ответственного и сохраните новую версию. Ранее созданные документы не изменяются.

Если изображение не настроено, приложение показывает это в блоке; документ можно сформировать с контактами без подписи. Если настроенный файл недоступен, генерация останавливается с ошибкой до переноса товаров. Изображения подписей остаются на Диске. Подписанные ссылки скачивания запрашиваются заново и не сохраняются в настройках, черновиках или снимках. Если вы заменяете содержимое существующего файла на Диске, ID остаётся тем же; для хранения прежнего изображения загрузите новую подпись отдельным файлом.

## Права и проверка на портале

Нужны права приложения `crm`, `catalog`, `disk`, `placement`, `user_basic`, а также права сотрудника на чтение сделки, профиля ответственного и файла подписи. Общий шаблон КП должен быть доступен для направления сделки.

Ссылка DOWNLOAD_URL запрашивается методом disk.file.get непосредственно перед генерацией. Портал должен иметь возможность скачать изображение по этой ссылке. Публичные ссылки на Диск приложение не создаёт.

В этой задаче реальный портал и изображения менеджеров не предоставлялись. Для первой проверки используйте тестовую сделку: настройте файл подписи, создайте DOCX и PDF и проверьте контакты, размер и положение изображения.

## Проверки

```sh
node tests/catalog.test.mjs
node tests/manager.test.mjs
```

Пройдены 18 регрессионных тестов. В Chromium с имитацией BX24 проверены настройка изображения, ФИО/почта/телефон, смена ответственного, сброс предыдущей подписи, сохранение ID файла в снимке, отсутствие подписанных URL в localStorage и оформление блока предпросмотра. Также повторно проверены поиск вариаций, товары без цены и ручной ввод цены.
