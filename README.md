## Запуск без Bitrix24

Требуются Python 3 и современный браузер. Устанавливать npm-пакеты не нужно.

```bash
cd /workspace/BITRIXXX
python3 -m http.server 8080 --bind 127.0.0.1
```

Откройте `http://127.0.0.1:8080`. Альтернатива с установленным Node.js: `npm start`. Открытие `index.html` через `file://` не подходит: приложение использует JavaScript-модули и загрузку JSON по HTTP.

Демонстрация загружается сразу: две строки макета, четыре торговых товара, покрытия и собственные связи «товар → чертёж → комплект КД». У НФГ есть два чертежа, чтобы проверить выбор при неоднозначном соответствии. Вес и обязательное производственное название не используются.

## Возможности пилота

- Выбор товаров, количество, покрытие и два свободных числовых коэффициента, включая ноль и отрицательные значения.
- Автоматический поиск чертежей и комплектов КД по ID товара; выбор чертежа при нескольких соответствиях.
- Несколько вариантов КП, создание варианта на основе текущего и сохранение версий.
- Предпросмотр предложения, печать средствами браузера и выгрузка снимка JSON.
- Подключение через официальный BX24 SDK, чтение сделки и каталога, загрузка справочников с Диска.
- Запись выбранного сохранённого КП в товарные позиции сделки с отдельным подтверждением.

Без папки истории на Диске варианты и версии хранятся **в браузере**. Они не являются общей историей CRM, не доступны другим менеджерам и могут исчезнуть при очистке данных сайта. Выгружайте снимки JSON для резервной копии. Общая история используется при настроенном `historyFolderId` и доступных правах Диска.

## Расчёт

Основной режим, соответствующий макету:

```text
Цена единицы = базовая цена каталога × коэффициент покрытия × К1 × К2
Сумма строки = цена единицы × количество
Итого = сумма строк
```

Также предусмотрен режим по структуре Excel:

```text
Цена единицы = (базовая цена + крепёж/покупные + доп. покрытие + доставка) × К1 × К2
```

Во втором режиме базовая цена заменяет исходное `вес × ставка за килограмм`; множитель покрытия дополнительно не применяется. Доплаты вводятся **на единицу изделия**. Связь с комплектом КД сама по себе не определяет их стоимость и количество. Это адаптация Excel без веса, а не буквальное воспроизведение исходного расчёта.

Деньги округляются до двух знаков. По умолчанию округляется сумма каждой строки; настройка позволяет сначала округлять цену единицы. Начальный демонстрационный итог — **1 948 708,34 ₽**. Макет показывает тот же расчёт с отображением целых рублей.

Для демонстрации используются покрытия из [data/coatings.example.json](data/coatings.example.json): цинкование `1,18`, окраска `1,12`. Загруженный пользователем файл сохранён отдельно как [data/prices.original.example.json](data/prices.original.example.json): в нём `1,15` и `1,08`. Его загрузка намеренно изменит расчёт. Устаревшее поле `prices_per_kg` игнорируется; цены берутся из каталога, а вес исключён.

## Подключение к сделке

Подготовьте локальное приложение Bitrix24 с правами `crm`, `catalog`, `disk`, `placement`, загрузите справочники на Диск и настройте вкладку `CRM_DEAL_DETAIL_TAB`. Нужен администратор портала. Используйте [инструкцию интеграции](docs/integration.md); форматы справочников и примеры находятся в [описании данных](docs/data-format.md).

Прототип не содержит токена или входящего вебхука. BX24 SDK использует авторизацию установленного приложения. ID демонстрационных товаров и файлов нельзя использовать для записи в рабочую сделку: перед пилотом на портале замените их реальными соответствиями и выберите реальные товары каталога.

## Проверка

Node.js 20+ используется только для автоматических проверок:

```bash
npm test
npm run check
```

Для проверки интерфейса запустите локальный HTTP-сервер. Проверка реальных REST-запросов, разрешений, встраивания в карточку и сохранения на Диск выполняется отдельно на тестовой сделке вашего портала: она требует установки приложения и доступа к Bitrix24.

## Границы прототипа

Расчёты выполняются в браузере. Для промышленного использования нужны серверная проверка расчётов и прав, согласованные правила ценообразования и одновременного редактирования. Встроенной транзакции между записью товарных позиций и суммой сделки нет; приложение проверяет состояние до записи и результат после неё, но это не блокировка конкурентных изменений. Сохранённые версии приложение не перезаписывает; это не запрет администраторам редактировать файлы на Диске.

Связи описывают документацию. Автодобавление комплектующих, производственный контур, распознавание содержимого PDF и шаблон клиентского DOCX в этот пилот не входят. Предпросмотр и печать позволяют проверить состав КП до проектирования итогового документа.
