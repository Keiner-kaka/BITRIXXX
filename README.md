# Конструктор КП ЮЗМ для Bitrix24

[Скачать установочный ZIP для Битрикс24](https://github.com/Keiner-kaka/BITRIXXX/raw/refs/tags/v2.4.2/dist/yuzm-kp-bitrix.zip)

Для загрузки локального статичного приложения используйте файл `yuzm-kp-bitrix.zip` по этой ссылке. В нём `index.html` лежит непосредственно в корне; включены все JS, CSS и JSON, необходимые приложению. Архив GitHub «Code → Download ZIP» и «Source code (zip)» содержит внешнюю папку репозитория. При загрузке такого архива Битрикс может сообщить: «В архиве отсутствует файл index.html».

В установочном ZIP версии 2.0.2 нет необязательного мастера `install.html`: Битрикс открывает конструктор сразу. Шаблон, файлы Диска и вкладка сделки настраиваются в открытом приложении. Если версия 2.0.1 остановилась на серой кнопке установки, в её карточке очистите «Путь для первоначальной установки», выключите «Приложение само завершает установку», сохраните и нажмите «Переустановить». «Путь вашего обработчика» с адресом `index.html` сохраните. Порядок автоматической установки описан в [документации Битрикс24](https://apidocs.bitrix24.ru/settings/app-installation/local-apps/installation-master.html).

Подключение проверяет загрузку BX24, ждёт контекст портала до 15 секунд и подтверждает доступ к REST и завершение установки через `app.info`. При недоступности основного сервера SDK используется второй официальный адрес. В случае сбоя доступна кнопка повторного подключения. В настройках → «Соединение с Битрикс24» можно скопировать диагностику: только версия, состояние фрейма, библиотеки и соединения; без токенов, ключей, адреса портала и содержимого `window.name`.

Конструктор коммерческих предложений во вкладке сделки Bitrix24. Сохраняет варианты и версии расчёта, поддерживает две формулы с тремя коэффициентами и создаёт документы через штатный REST-генератор Bitrix24 по зарегистрированному шаблону. Рабочий портал при разработке и локальной проверке не использовался.

## Запуск без Bitrix24

Требуются Python 3 и современный браузер. Устанавливать npm-пакеты не нужно.

```bash
cd /workspace/BITRIXXX
python3 -m http.server 8080 --bind 127.0.0.1
```

Откройте `http://127.0.0.1:8080`. Альтернатива: `npm start`. Открытие `index.html` через `file://` не подходит: приложение загружает JavaScript-модули и JSON по HTTP. В демонстрационном режиме доступны расчёт, варианты, версии и предпросмотр; генерация документов требует подключения к порталу.

## Расчёт

| Режим | Цена единицы | Сумма строки |
| --- | --- | --- |
| Каталог | `базовая цена × К1 × К2 × К3` | `цена единицы × количество` |
| Excel | `цена за кг × вес единицы × К1 × К2 × К3 + метизы за единицу` | `цена единицы × количество` |

Для «Окраска» и «Горячее цинкование + окрашивание RAL» доступен текстовый номер цвета в каждой строке. Например, в КП будет «Окраска RAL 9005» или «Горячее цинкование + окрашивание RAL 7035 матовый». Номер сохраняется в вариантах и версиях, не меняет цену и передаётся в существующую метку `{YuzmCoating}`. Старые справочники покрытий получают комбинированный вариант при загрузке в черновик. Поле даты отгрузки и признак «Нестандарт» удалены.

К3 — коэффициент покраски и покрытия, который менеджер задаёт вручную для каждой строки. Покрытие — только выбранное наименование для КП; справочник не умножает цену автоматически. У каждой товарной строки есть текстовый срок исполнения. Связи с чертежами и технической документацией исключены.

В Excel вес и цена метизов указываются **на одну единицу изделия**. Метизы прибавляются после применения коэффициентов к стоимости металла. Отдельные доплаты за доставку и покрытие в эту формулу не входят. Цены за кг можно загрузить отдельным JSON-файлом с Диска Bitrix24 или локально; ключи файла — ID товаров каталога. Для отсутствующей цены требуется заполнение, она не заменяется нулём.

Деньги округляются до двух знаков. Настройка позволяет округлять сумму строки либо сначала цену единицы. Для записи в товары сделки используется округление цены единицы. Форматы справочников и правила перехода со старых черновиков описаны в [docs/data-format.md](docs/data-format.md).

## Товары и вариации

В выборе из каталога доступны обычные товары и активные вариации. В режиме «По названию» ищите часть названия, включая цифры: например `СФГ`, `700` или `СФГ-700`. Для точного ID выберите «По ID». Поиск основного товара возвращает его вариации отдельными позициями; можно искать и саму вариацию. В интерфейсе вариации отмечены, в КП передаётся их собственное наименование.

Выбранная вариация использует собственные ID, базовую цену и валюту. В режиме Excel цена металла загружается по ID вариации, а вес вводится для единицы выбранного исполнения. В товары сделки переносится ID вариации. Цена основного товара и его цена металла не заменяют отсутствующие данные вариации. Выбор сохраняется в черновике и версии КП.

## Документы и история

Используется приложенный пользователем DOCX без изменения: [data/templates/kp-yuzm-bitrix24.docx](data/templates/kp-yuzm-bitrix24.docx). Его нужно зарегистрировать в генераторе документов вашего портала. Администратор выбирает один зарегистрированный шаблон в настройках → «Документы КП в Битрикс24» → «Общий шаблон КП» и нажимает «Сохранить настройки». Выбор хранится на портале и действует для всех менеджеров этого приложения, сделок и браузеров. Шаблон можно сменить там же; отдельного выбора для вариантов нет. Перед генерацией общий выбор повторно читается с портала. Кнопка печати из предпросмотра удалена; ссылки на DOCX и PDF выдаёт генератор Битрикс24. Приложение передаёт в документ строки сохранённого расчёта, наименование покрытия и срок исполнения; при создании документа приложение обязательно заменяет все товары сделки строками выбранной сохранённой версии и проверяет результат повторным чтением. До записи проверяются данные и доступность шаблона. При отказе записи, конфликте или неподтверждённом результате документ не создаётся. Если товары уже записаны, а генератор отказал, интерфейс сообщает об этом; автоматического отката товаров нет. PDF может появиться позже: статус и ссылки обновляются без повторного создания документа.

Условия КП редактируются отдельно для каждого варианта и сохраняются вместе с версией. Для оплаты предусмотрены варианты 40/60, 50/50 и 100% предоплаты с последующим редактированием текста. Для крепежа доступны три редактируемые предустановки: крепеж на базе болтов включён (гальваническое покрытие), крепеж в комплект не входит, крепеж на базе шпилек включён (гальваническое покрытие). При открытии сделки имя, фамилия, должность и рабочий телефон текущего ответственного автоматически подставляются в подпись. Требуется разрешение «Пользователи (базовый) — `user_basic`». Если рабочего телефона нет, его вводят вручную; личный мобильный номер не используется. Все поля можно править. Ручные правки сохраняются после перезагрузки и не заменяются автоматически; кнопка «Подставить данные ответственного» заново заполняет подпись текущего варианта из профиля. Подпись сохраняется в версии КП и не обновляется в старых версиях. Начальные формулировки условий взяты из образца; адрес доставки нужно проверить для конкретного КП. Приложение добавляет разделяющий пробел между должностью и именем при передаче в соседние метки исходного DOCX; файл шаблона остаётся неизменным.

Сохранение версии создаёт отдельный снимок. Расчёты и ранее сохранённые версии не меняются при последующей правке справочников или черновика. Ссылки на созданные документы хранятся отдельно от снимка в данных варианта этого браузера. Старые снимки первого формата открываются со своими исходными суммами.

Без `historyFolderId` варианты и версии хранятся **в этом браузере**: они не доступны другим менеджерам и могут исчезнуть при очистке данных сайта. Можно выгрузить снимки JSON. Общая история работает при настроенной папке Диска и доступных правах. Дополнительно можно перенести текущий расчёт в товары сделки отдельной кнопкой с подтверждением. Предпросмотр и сохранение версии сами по себе товары не меняют; создание документа выполняет перенос обязательно, без отдельного подтверждения.

## Подключение и проверка

В версии 2.4.2 исправлен повтор первой страницы при чтении каталога через официальный BX24 SDK, из-за которого поиск даже с 51 совпадением показывал «слишком много совпадений». Поиск не загружает весь каталог при открытии окна: введите название или ID и нажмите «Найти». При более чем 500 совпадениях уточните запрос. Ошибки каталога и тайм-ауты не скрываются за `crm.product.get`; безопасный журнал последних запросов доступен в настройках подключения.

Приложение использует официальный BX24 SDK и авторизацию установленного приложения; токенов и входящего вебхука в исходном коде нет. Подготовка вкладки, файлов Диска и шаблона описана в [docs/integration.md](docs/integration.md). До работы с настоящей сделкой выберите реальные товары каталога: демонстрационные ID и цены не являются данными портала.

Node.js 20+ нужен только для автоматических проверок:

```bash
npm test
npm run check
```

Состав локальной проверки и сценарии приёмки на портале приведены в [docs/validation.md](docs/validation.md). Реальные REST-вызовы, права, шаблон и PDF нужно проверить на тестовой сделке после установки приложения.

`npm run package` создаёт два архива: `dist/yuzm-kp-bitrix.zip` для загрузки статичного приложения и `dist/yuzm-kp-prototype.zip` с полным проектом, PHP-обработчиками, DOCX и документацией. Сборщик проверяет корневой `index.html`, состав runtime-файлов и контрольные суммы.

## Границы решения

Расчёты выполняются в браузере. Для промышленного использования нужны серверная проверка расчётов и прав, согласованные налоговые правила и управление одновременным редактированием. Проверки до и после записи товарных строк уменьшают риск конфликтов, но не создают транзакцию между товарами и суммой сделки. Приложение не перезаписывает снимки; это не ограничивает права администраторов на изменение файлов Диска.

С версии 2.3.0 новый документ из любой сохранённой версии создаётся по текущему общему шаблону, повторно прочитанному с портала перед генерацией. Поле `documentTemplateId` в снимке остаётся сведением о выборе на момент сохранения и не управляет генерацией. Товары, цены, сроки, условия и подпись берутся из снимка. Уже созданные документы сохраняются со своими ID и шаблонами; после смены общего шаблона можно создать новый документ из той же версии.
