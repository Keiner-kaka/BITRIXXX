# Конструктор КП ЮЗМ для Bitrix24

[Скачать установочный ZIP для Битрикс24](https://github.com/Keiner-kaka/BITRIXXX/raw/refs/tags/v2.0.3/dist/yuzm-kp-bitrix.zip)

Для загрузки локального статичного приложения используйте файл `yuzm-kp-bitrix.zip` по этой ссылке. В нём `index.html` лежит непосредственно в корне; включены все JS, CSS и JSON, необходимые приложению. Архив GitHub «Code → Download ZIP» и «Source code (zip)» содержит внешнюю папку репозитория. При загрузке такого архива Битрикс может сообщить: «В архиве отсутствует файл index.html».

В установочном ZIP версии 2.0.2 нет необязательного мастера `install.html`: Битрикс открывает конструктор сразу. Шаблон, файлы Диска и вкладка сделки настраиваются в открытом приложении. Если версия 2.0.1 остановилась на серой кнопке установки, в её карточке очистите «Путь для первоначальной установки», выключите «Приложение само завершает установку», сохраните и нажмите «Переустановить». «Путь вашего обработчика» с адресом `index.html` сохраните. Порядок автоматической установки описан в [документации Битрикс24](https://apidocs.bitrix24.ru/settings/app-installation/local-apps/installation-master.html).

Версия 2.0.3 проверяет загрузку BX24, ждёт контекст портала до 15 секунд и подтверждает доступ к REST и завершение установки через `app.info`. При недоступности основного сервера SDK используется второй официальный адрес. В случае сбоя доступна кнопка повторного подключения. В настройках → «Соединение с Битрикс24» можно скопировать диагностику: только версия, состояние фрейма, библиотеки и соединения; без токенов, ключей, адреса портала и содержимого `window.name`.

Конструктор коммерческих предложений во вкладке сделки Bitrix24. Сохраняет варианты и версии расчёта, поддерживает две формулы с тремя коэффициентами и создаёт документы через штатный REST-генератор Bitrix24 по зарегистрированному шаблону. Рабочий портал при разработке и локальной проверке не использовался.

## Запуск без Bitrix24

Требуются Python 3 и современный браузер. Устанавливать npm-пакеты не нужно.

```bash
cd /workspace/BITRIXXX
python3 -m http.server 8080 --bind 127.0.0.1
```

Откройте `http://127.0.0.1:8080`. Альтернатива: `npm start`. Открытие `index.html` через `file://` не подходит: приложение загружает JavaScript-модули и JSON по HTTP. В демонстрационном режиме доступны расчёт, варианты, версии и предпросмотр; генерация документов требует подключения к порталу.

## Расчёт

| Режим | Цена единицы | Сумма строки |
| --- | --- | --- |
| Каталог | `базовая цена × К1 × К2 × К3` | `цена единицы × количество` |
| Excel | `цена за кг × вес единицы × К1 × К2 × К3 + метизы за единицу` | `цена единицы × количество` |

К3 — коэффициент покраски и покрытия, который менеджер задаёт вручную для каждой строки. Покрытие — только выбранное наименование для КП; справочник не умножает цену автоматически. У каждой товарной строки есть текстовый срок исполнения. Связи с чертежами и технической документацией исключены.

В Excel вес и цена метизов указываются **на одну единицу изделия**. Метизы прибавляются после применения коэффициентов к стоимости металла. Отдельные доплаты за доставку и покрытие в эту формулу не входят. Цены за кг можно загрузить отдельным JSON-файлом с Диска Bitrix24 или локально; ключи файла — ID товаров каталога. Для отсутствующей цены требуется заполнение, она не заменяется нулём.

Деньги округляются до двух знаков. Настройка позволяет округлять сумму строки либо сначала цену единицы. Для записи в товары сделки используется округление цены единицы. Форматы справочников и правила перехода со старых черновиков описаны в [docs/data-format.md](docs/data-format.md).

## Документы и история

Используется приложенный пользователем DOCX без изменения: [data/templates/kp-yuzm-bitrix24.docx](data/templates/kp-yuzm-bitrix24.docx). Его нужно зарегистрировать в генераторе документов вашего портала. В настройках можно выбрать зарегистрированный шаблон по умолчанию, а в варианте КП — другой шаблон. Приложение передаёт в документ строки сохранённого расчёта, наименование покрытия и срок исполнения; создание документа не записывает товары в сделку. PDF может появиться позже: статус и ссылки обновляются без повторного создания документа.

Условия КП редактируются отдельно для каждого варианта и сохраняются вместе с версией. Для оплаты предусмотрены варианты 40/60, 50/50 и 100% предоплаты с последующим редактированием текста. Имя, должность и телефон менеджера также редактируются. Начальные формулировки условий взяты из образца; адрес доставки нужно проверить для конкретного КП.

Сохранение версии создаёт отдельный снимок. Расчёты и ранее сохранённые версии не меняются при последующей правке справочников или черновика. Ссылки на созданные документы хранятся отдельно от снимка в данных варианта этого браузера. Старые снимки первого формата открываются со своими исходными суммами.

Без `historyFolderId` варианты и версии хранятся **в этом браузере**: они не доступны другим менеджерам и могут исчезнуть при очистке данных сайта. Можно выгрузить снимки JSON. Общая история работает при настроенной папке Диска и доступных правах. Применение выбранной версии к товарам сделки остаётся отдельным действием с подтверждением замены строк.

## Подключение и проверка

Приложение использует официальный BX24 SDK и авторизацию установленного приложения; токенов и входящего вебхука в исходном коде нет. Подготовка вкладки, файлов Диска и шаблона описана в [docs/integration.md](docs/integration.md). До работы с настоящей сделкой выберите реальные товары каталога: демонстрационные ID и цены не являются данными портала.

Node.js 20+ нужен только для автоматических проверок:

```bash
npm test
npm run check
```

Состав локальной проверки и сценарии приёмки на портале приведены в [docs/validation.md](docs/validation.md). Реальные REST-вызовы, права, шаблон и PDF нужно проверить на тестовой сделке после установки приложения.

`npm run package` создаёт два архива: `dist/yuzm-kp-bitrix.zip` для загрузки статичного приложения и `dist/yuzm-kp-prototype.zip` с полным проектом, PHP-обработчиками, DOCX и документацией. Сборщик проверяет корневой `index.html`, состав runtime-файлов и контрольные суммы.

## Границы решения

Расчёты выполняются в браузере. Для промышленного использования нужны серверная проверка расчётов и прав, согласованные налоговые правила и управление одновременным редактированием. Проверки до и после записи товарных строк уменьшают риск конфликтов, но не создают транзакцию между товарами и суммой сделки. Приложение не перезаписывает снимки; это не ограничивает права администраторов на изменение файлов Диска.
